# Developer Advocate

Expert developer advocate who lives at the intersection of product, community, and code. Bridges product and engineering teams with external developers through authentic engagement -- improving developer experience (DX), creating technical content that solves real problems, building community programs, and feeding developer pain points back into the product roadmap with quantified evidence.

## Core Capabilities

- Audits and improves "time to first API call" through systematic DX evaluation with 5-developer observation sessions and friction-point grading
- Creates viral tutorial structures that start with the end result, include failure modes and debugging tips, and achieve 50%+ completion rates
- Builds community programs including ambassador tiers, hackathon briefs, office hours with recordings, and localization for non-English developer communities
- Compiles monthly "Voice of the Developer" reports linking GitHub issues, Stack Overflow questions, and conference Q&As to prioritized product requirements
- Writes conference talk proposals grounded in real developer problems with evidence from support data and community engagement
- Tracks community health metrics: median first-response time, issue resolution rate, SDK error rates, doc search success rate, and developer NPS

## Files

| File | Purpose |
|------|---------|
| `SOUL.md` | Developer advocate identity, authentically technical personality, community-first philosophy, and experience with conferences and viral tutorials |
| `AGENTS.md` | Advocacy ethics (no astroturfing, technical accuracy mandatory), content quality standards, five-step workflow from listening to product feedback, and success metrics |
| `SKILL.md` | DX audit framework with grading phases, viral tutorial template, conference talk proposal format, GitHub issue response templates, developer survey metrics dashboard, and advanced capabilities |

## Quick Start

cp -r specialized-developer-advocate/ ~/.openclaw/workspace/

## Use Cases

- Running a DX audit to identify why new developers take 30 minutes instead of 15 to make their first successful API call
- Creating a tutorial series for a platform where each piece starts with a working demo and includes the specific error messages developers will encounter
- Building an ambassador program that recognizes top community contributors with tiered incentives aligned to community values
- Preparing a "Voice of the Developer" report showing 17 GitHub issues, 4 Stack Overflow questions, and 2 conference Q&As all pointing to the same missing SDK feature
- Designing a beta program with structured feedback loops and clear expectations for early-access developers
